# NORI VEHICLE RENTAL — BÁO CÁO KIỂM TOÁN HIỆU NĂNG, KHẮC PHỤC SỰ CỐ & NGHIỆM THU PRODUCTION

- **Ngày thực hiện**: `2026-11-20`
- **Phiên bản kiểm toán**: `v2.6.1` (tối ưu toàn hệ thống sau tích hợp thanh toán trực tuyến `v2.6.0`)
- **Môi trường đo đạc**: Windows (`win32`) · Node.js `v24.22.3` · `pnpm` · Next.js `16.4.6` (Turbopack) · React `19.3.1` · Payload CMS `4.0.0-beta.8` · SQLite (`./nori.db`, bản sao cô lập khi test/benchmark) · Chromium headless CDP (`@playwright/test 1.65.1`)
- **Cấu hình đo Lab**: Tối thiểu **5 lượt đo độc lập** trên mỗi route công khai; Desktop `1440×1000` (unthrottled) và Mobile `375×812` (`Slow 4G`: `1.6 Mbps` down / `750 Kbps` up / `150 ms RTT`, `CPU 4x throttling`), tắt HTTP cache trình duyệt để đo cold-render nhất quán.
- **Lưu ý chuẩn đo lường**: Báo cáo tách bạch rõ **Lab metrics** (`LCP`, `CLS`, `TBT`, `TTFB`, `FCP`) với **Field metrics (RUM p75)**. `TBT` (lab) **không phải** `INP` (field). Vì hệ thống chưa có traffic người dùng thật trên domain production, **Field CWV p75 = `UNAVAILABLE`**.

## 6. Cơ sở dữ liệu: EXPLAIN QUERY PLAN & Đánh giá SQLite vs PostgreSQL

### 6.1. Kết quả `EXPLAIN QUERY PLAN` sau tối ưu 7 Composite Indexes

| Truy vấn trọng yếu                                              | Trước (Baseline)                              | Sau (After — 7 Composite Indexes)                                                                        |
| :-------------------------------------------------------------- | :-------------------------------------------- | :------------------------------------------------------------------------------------------------------- |
| `payments` theo `booking_id ORDER BY created_at DESC`           | `SEARCH` + `USE TEMP B-TREE FOR ORDER BY`     | `SEARCH payments USING INDEX payments_booking_created_idx (booking_id=?)`                                |
| Quét `payments` hết hạn (`status IN (...) AND expires_at <= ?`) | `SEARCH` theo `status` đơn (quét mọi pending) | `SEARCH payments USING INDEX payments_status_expires_idx (status=? AND expires_at<?)`                    |
| `bookings` theo `customer_id ORDER BY created_at DESC`          | `SEARCH` + `USE TEMP B-TREE FOR ORDER BY`     | `SEARCH bookings USING INDEX bookings_customer_created_idx (customer_id=?)`                              |
| `bookings` theo `status ORDER BY created_at DESC`               | `SEARCH` + `USE TEMP B-TREE`                  | `SEARCH bookings USING INDEX bookings_status_created_idx (status=?)`                                     |
| `notifications` theo `customer_id ORDER BY created_at DESC`     | `SEARCH` + `USE TEMP B-TREE FOR ORDER BY`     | `SEARCH notifications USING INDEX notifications_customer_created_idx (customer_id=?)`                    |
| `vehicles` theo `model_id AND status`                           | Index đơn `model_id`                          | `SEARCH vehicles USING INDEX vehicles_model_status_idx (model_id=? AND status=?)`                        |
| `rental_days` theo `vehicle_id` & khoảng ngày                   | `SEARCH` không covering                       | `SEARCH rental_days USING COVERING INDEX rental_days_vehicle_day_idx (vehicle_id=? AND day>? AND day<?)` |

### 6.2. Đánh giá Kiến trúc SQLite vs PostgreSQL (Không rewrite sớm)

- **Hiện trạng đo được**: Với `SQLite WAL + synchronous=NORMAL + busyTimeout=5000`, hệ thống đạt **669.5 req/s** ở 100 VUs đọc hỗn hợp và xử lý **20 write đồng thời trong 323 ms với `0` lỗi `SQLITE_BUSY`**. SQLite hoàn toàn đáp ứng giai đoạn vận hành 1 node (MVP / thương mại nhỏ & vừa, `< 50` write TPS liên tục).
- **Ngưỡng kích hoạt chuyển đổi sang PostgreSQL (`@payloadcms/db-postgres`)**: Chỉ thực hiện trong một giai đoạn riêng có diễn tập migration & rollback khi đạt một trong các điều kiện: (1) triển khai đa instance ngang (horizontal scaling / multi-region serverless không dùng chung đĩa local); (2) lưu lượng ghi đồng thời vượt `~50–100 write TPS` xuất hiện `SQLITE_BUSY` p99 > 200 ms; (3) yêu cầu High Availability failover tự động / Point-in-Time Recovery dạng managed DB.
